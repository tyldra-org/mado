# M0 prototype

Load for any M0 task. M0 answers the open engine questions that every later
spec marks "(verify in M0)". Its report is the contract those specs defer to,
so precision matters more here than anywhere.

## Rules

- Code goes in `proto/` only. Nothing in `crates/`, `app/`, `ui/` or
  `inject/` changes, and nothing imports from `proto/`.
- The wiring phase does not apply. Replace it with experiment rigor:
  - each experiment runs from one documented command;
  - it records the macOS, WebKit, Xcode and Rust versions it ran with;
  - it measures numbers where the question is about size, time or limits,
    with the method and the number of runs;
  - it tests the failure case the later spec depends on, not only the happy
    one.
- Prototype code is throwaway but not careless: it must show what the report
  claims, and nothing more.

## Report format

One section per experiment in `../mado-docs/research/m0-report.md`:

~~~markdown
### Experiment 7: <name>
Question: the exact question from 16 §5.
Method: command, fixture and environment (OS, engine, toolchain versions).
Result: what happened, with numbers and an output excerpt.
Grade: verified on this Mac | tested | untested.
Evidence: proto/<path>, screenshot or log path.
Decision: the approach chosen, or the fallback and why.
Specs affected: section numbers that change, and the Spec issue for each.
~~~

## Windows

Write each Windows experiment's steps under a "Windows run sheet" section:
prerequisites, the exact commands, what to record and how to grade it. Mark
it "untested on Windows" until someone runs it. Never guess a Windows result.

## Exit

When every macOS experiment is recorded, set the milestone status to `in
progress (Windows pending)`. Each "(verify in M0)" that the report answers
gets a Spec issue pointing at its section, so M1 starts from facts.
